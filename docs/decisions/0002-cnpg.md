# 0002 Postgres の運用は CloudNativePG に任せる

日付: 2026-10-13

## 決定

データプレーン（Postgres の起動・フェイルオーバー・バックアップ・PITR）は CloudNativePG に任せ、
自作するのはその上のコントロールプレーン（DB の払い出し・一覧・削除・ブランチ）だけにする。

## 理由

- `Cluster` 1枚で起動・レプリカ・フェイルオーバー・メトリクスまで揃う。Patroni などの外部部品が要らない
- リカバリが常に「新しい Cluster をバックアップから bootstrap する」設計なので、
  `recoveryTarget` を指定するだけで「ある時点の複製」＝ブランチ機能になる
- 比較した他候補: KubeBlocks（多エンジンだが Postgres は一部品）、Crunchy PGO（Patroni 依存・2025 にリリース停滞）、
  StackGres（AGPL）

## 注意

- 1.30 で in-tree の Barman バックアップは削除済み。バックアップは Barman Cloud Plugin を使う（前提に cert-manager）
- `local-path` は VolumeSnapshot 非対応。ブランチはオブジェクトストア経由で作る
